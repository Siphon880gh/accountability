# Accountability design guide

## Design Context

### Users
People maintaining personal goals with accountability partners. They check in frequently, reflect on a day, add visual evidence, and look back over months. The creator explicitly selected the **Focused training log** direction. The interface should make the next action clear without shaming missed days.

### Brand Personality
Focused, encouraging, grounded. Use direct language about effort and continuity. Gaps are useful records, not failures. Avoid clinical language, exaggerated celebration, or productivity guilt.

### Aesthetic Direction
A modern training log: ink navy, warm white paper, deliberate yellow accents, strong condensed headings, and legible sans-serif body text. Postop is the explicit anti-reference: do not return to green/teal clinical styling, soft medical dashboard cards, or Inter-led typography.

- Ink/navy: `#172943`; page: `#f4f3ed`; paper: `#fffef8`.
- Action yellow: `#efc541`, with navy text. Never use yellow text on white.
- Activity marks: dark gold `#af7c05`, distinct from quiet empty cells.
- Secondary text: `#5c6674`; rules: `#d7d9d9`.
- Display font stack: Avenir Next Condensed, Franklin Gothic Medium, Arial Narrow, sans-serif.
- Body stack: Avenir Next, Trebuchet MS, sans-serif. System-installed fonts avoid remote requests or build dependencies; appearance varies with installed fonts.
- Large, left-aligned condensed headlines; measured upper-case eyebrows; ruled sections and square-edged records. Compact 4px control radii; no decorative shadows, gradients, or glass effects.

### Design Principles
1. **Show the work.** Heatmaps, check-ins, month summaries, notes, and images are the product's visual substance.
2. **Make scale explicit.** Months show the long view; selecting a month opens its days. Include counts and text cues, not color alone.
3. **Give the next action priority.** Yellow belongs to key actions; secondary controls remain quieter.
4. **Keep the record connected.** Image libraries are isolated per accountability partner. Thumbnails lead to the precise note, partner, goal, and date. Multiple references remain visible.
5. **Fit daily use.** Keyboard access, visible focus, labelled editor controls, reduced-motion support, mobile wrapping, readable contrast, and honest loading/error states are required.

## Implementation constraints
Plain `index.php` plus PHP includes and `api.php`; no router, Composer/vendor, npm, runtime package dependency, or bundler. Native ES modules handle the browser UI. Notes remain IndexedDB-backed; image files use SHA-256 filenames on the PHP server. Sanitize rich HTML both on save and display. Never render arbitrary pasted attributes or remote image URLs.

## Recent interaction decisions

- Goal counts are single-select toggle filters. Choosing another goal replaces the current selection; clicking it again clears it. Match the selected normalized goal, gray out other partner cards, switch matching carousels to the selected goal, and show an explicit filter bar with an × clear control.
- Add a compact vertical separator after Sunday in the day strip; Monday begins the next week.
- Tag entry is a quiet, compact multi-select chip row above the full-width rich note editor. Tags are optional. Avoid numbered steps and a competing tag column. Manage names/colors centrally per goal; use small colored date dots with a named legend, never color alone. Note actions remain quiet beside the chips.
- Screenshot capture was stopped at the user’s request; do not resume without a new request.

- Workspace hierarchy uses three named regions: Progress, Choose a day, and Notes & reflection. The date selector sits on a tinted navigation surface; the current date is explicit; the composer is a distinct paper surface below saved notes. Avoid treating every heading, action, and divider as equally important.
- An expanded editor moves the same live draft into a large dialog. Done editing or Escape returns the draft unchanged; saving remains explicit in the note form.
- Partner-card non-interactive areas open the workspace. Nested controls and heatmap scrolling retain their behavior; text selection and dragging do not navigate. Keep the native Open workspace button for keyboard access.

## Review checklist
- At 390px, no page overflow; toolbars wrap; all actions remain reachable.
- At desktop widths, partner overview, month selection, and note editing have distinct visual hierarchy.
- Keep images bounded without stretching. Image-only notes are valid.
- Preserve plain-text notes, original goal labels, and per-partner activity semantics.
- Update README screenshots when visual flows change. Use synthetic data only.
